## Agent access

Read [SEO and agent readiness](seo-and-agent-readiness.md) for why these components exist, how requests flow, and how to choose future improvements. This document owns the release procedure.

`scripts/agent-content.mjs` reads the same portfolio data as the homepage and generates `index.md`, `llms.txt`, `sitemap.xml`, `robots.txt`, `404.html`, and the About, Contact, and Privacy pages in HTML and Markdown. Production JSON-LD and Open Graph metadata are inserted by the publisher. The homepage body and interaction code are unchanged. `assets/portfolio/info.css` gives the new text pages the existing palette without remote fonts or scripts. Update `lastmod` in the content module when published copy or metadata changes; do not advance it merely for a rebuild. The sitemap lists the four canonical portfolio pages, not alternate representations, assets, or development prototypes.

The identity is `Person`, with the public email and profile links from portfolio data. Do not invent an Organization, postal address, prices, or availability to satisfy a scoring heuristic. A business identity and public address require an owner decision. Privacy copy describes the application’s actual local theme storage and external dependencies; recheck it when providers or collection behavior change.

GitHub Pages cannot negotiate representations by request header. `workers/agent-negotiation.mjs` adds this behavior on the existing Cloudflare proxy using a Worker **route**, keeping GitHub Pages as the origin. The Worker fetches current Markdown files from Pages rather than bundling a second copy. HTML requests retain the original HTML body. Negotiated responses include `Vary: Accept` and bypass shared caching because Cloudflare’s default cache key ignores `Accept`. Runtime assets keep their existing caching. Missing paths return Markdown with HTTP 404; a missing or invalid Markdown representation returns 502. Unsupported homepage representations return 406. The Worker also honors quality weights, exclusions, wildcards, and HEAD requests.

Run `make generate test worker-check` before release. The tests check negotiation, real generated content, schema, metadata, discovery formats, substantive trust-page content, and unchanged homepage body. `worker-check` bundles with pinned Wrangler 4.152.0 without publishing. No external services or credentials are used by these checks. `make verify-public` performs read-only HTTP checks against the live site, including all generated files and both representations; it intentionally fails until both Pages and the Worker route are deployed.

Publish the static files through the existing `master` Pages release first. Confirm `/index.md`, `/llms.txt`, `/sitemap.xml`, and the three trust pages are available before enabling negotiation. Deploy the exact checked Worker through the signed-in Cloudflare dashboard, or run `pnpm dlx wrangler@4.152.0 deploy --config workers/wrangler.jsonc` with an authorized Cloudflare account. The route is `anmoltomer.com/*` in the `anmoltomer.com` zone. This is a route in front of existing DNS, not a Worker Custom Domain; do not replace DNS or migrate the origin. Disable the unused workers.dev address and preview URLs to match the checked configuration. Check any existing route before replacing it.

After deployment run `make verify-public`. Also fetch `/` with `Accept: text/html` and `Accept: text/markdown`, and a unique missing path with `Accept: text/markdown`; inspect final status, Content-Type, Vary, and body. Parse the served sitemap as XML, inspect the browser at desktop and 390px, and compare the active Worker code with the checked source. A Wrangler dry run is not production evidence. Removing the Worker route restores normal GitHub Pages responses; keep the published Markdown and discovery files available. For future changes, publish static representations before deploying any Worker that depends on them.

Protocol references: [HTTP negotiation](https://www.rfc-editor.org/rfc/rfc9110.html#section-12.5.1), [Accept Markdown](https://acceptmarkdown.com/reference), [llms.txt](https://llmstxt.org/), [Sitemaps](https://www.sitemaps.org/protocol.html), [Person](https://schema.org/Person), [Cloudflare routes](https://developers.cloudflare.com/workers/configuration/routing/routes/), and [Cloudflare cache behavior](https://developers.cloudflare.com/cache/concepts/cache-control/).
