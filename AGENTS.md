# Portfolio

Read `docs/portfolio-deployment.md` for source selection, generation, checks, hosting, release verification, and rollback.

- Edit portfolio copy in `prototype/v2/data.js` and the active design in `prototype/v2/07-2-trail-meadow/`. Root `index.html` and `assets/portfolio/` runtime copies are generated by `make generate`.
- Agent content and trust-page copy live in `scripts/agent-content.mjs`; keep them consistent with the public portfolio. Update its explicit last-modification date when published copy changes.
- Use truthful Person schema. Do not invent business details or publish a personal address.
- Keep the homepage design, theme, animations, and mobile behavior intact. Changes to production metadata must not alter its body.
- Run `make generate test worker-check` before release and `make verify-public` afterward. Local tests and bundling use no external services or credentials; public verification makes read-only network requests.
- GitHub Pages publishes `master` at `/`. Cloudflare negotiation uses a Worker route in front of Pages. Check current provider state before publishing; preserve `CNAME` and existing DNS.
- New checkouts need Node.js and pnpm for the Wrangler dry run. No environment files, database, or application dependencies are required. Static preview can use a local server on a free port; Worker deployment requires separately authorized Cloudflare access.
- Keep local evidence in ignored `output/`. Stage only in-scope files. Never add commit co-authorship or use `rm`.
